# P11c · MT5 bridge + edge check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring Farjad's real MetaTrader 5 trades into AlphaBoard and answer one question with numbers: do his entries beat random entries on the same symbol, side, stop distance and holding time?

**Architecture:** An MQL5 script (`mql5/ExportDeals.mq5`, same idea as `ExportM1.mq5`) writes the account's whole deal history to a CSV with fixed columns (UTC times, ids, stops, costs, magic). A pure parser rebuilds positions from deals; an owner-scoped importer writes them to `JournalEntry` (`pnlSource: "MT5"`, idempotent by `legacyId`); a pure edge check compares each trade with random entries simulated on a Lab dataset of the same symbol. Shown in Admin → Lab ("Your trades").

**Spec:** `docs/superpowers/plans/2026-10-20-p11-honest-numbers-and-strategy-lab.md` § P11c — refined: the MT5 HTML/XLSX report is localized (Farjad's is Persian) and only a PDF was at hand, so a script export replaces report parsing. The EA → API push stays a later step.

## Global Constraints
- Imports never duplicate: `legacyId = mt5:<login>:<positionId>`; re-import updates nothing that already exists.
- Only closed positions are imported (an open position has no result yet).
- Money stays in the account currency of the export; nothing is converted or invented. R is computed only when the opening deal carries a stop.
- The edge check states its sample size and says "not enough trades yet" under 30 trades; it never claims an edge without a significance figure.

## Files
| File | Responsibility |
|---|---|
| `mql5/ExportDeals.mq5` | Script: `HistorySelect(0, now)`, every BUY/SELL deal → `Files/Deals_<login>.csv` |
| `lib/mt5/deals.ts` | Pure: `parseDealsCsv(text)`, `positionsFromDeals(deals)` (partial closes, net P&L = profit + swap + commission + fee) |
| `lib/mt5/import.ts` | Owner-scoped import into `JournalEntry` (create-only, by legacyId) |
| `lib/lab/edge.ts` | Pure: `edgeCheck(trades, bars, opts)` — per trade, K random entry times in the same calendar month, same side, stop distance and holding time; difference in R with a bootstrap 95 % interval |
| `app/api/admin/lab/trades/route.ts` | POST upload (multipart, outside the proxy like the dataset upload), GET imported MT5 trades |
| `app/api/admin/lab/edge/route.ts` | POST `{ symbol, datasetId }` → edge result (synchronous; cheap) |
| `components/admin/lab/LabWorkbench.tsx` | "Your trades" panel: upload, summary, edge verdict |

## CSV columns (ExportDeals)
`deal,order,position,time_utc,type,entry,symbol,volume,price,sl,tp,commission,swap,profit,fee,magic,comment,login=<login>,currency=<ccy>` — `type` 0 buy / 1 sell, `entry` 0 in / 1 out / 2 inout / 3 out_by.

## Tasks
1. **MQL5 script** — compile with the Wine MetaEditor CLI to 0 errors; copy to the terminal's `MQL5/Scripts`.
2. **parser + positions (TDD)** — a full round trip (in → out), a partial close (in → out half → out half), a reversal (`inout`), a position still open (skipped), costs summed, side and initial stop from the opening deal, holding time, symbol suffix kept (`XAUUSD.ec`).
3. **importer (DB TDD)** — creates `JournalEntry` rows with `pnlSource: "MT5"`, entry/exit price, `pnlPercent` null (no margin known), notes carrying `$` result and magic; a second import of the same file creates nothing; another user is isolated.
4. **edge check (TDD)** — on a synthetic random walk a set of random trades shows no edge (interval contains 0); trades placed with hindsight (always the side that later moved first) show a clear positive edge; fewer than 30 trades → verdict says so.
5. **API + panel** — upload, list, run the edge check against a chosen Lab dataset; verify in the app with Farjad's real export when he runs the script; gates; commit; Notion.
