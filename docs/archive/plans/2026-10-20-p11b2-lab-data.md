# P11b-2 · Strategy Lab data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real historical bars for the Lab engine (`lib/lab`, P11b-1): Binance klines for crypto, OANDA bid/ask candles for forex and metals (so the spread is real), and the MT5 `ExportM1.mq5` CSV for a broker's own prices — stored per user, compressed, owner-only.

**Architecture:** Pure codecs and parsers (`lib/lab/data/encode.ts`, `mt5csv.ts`) are unit-tested; fetchers (`binance.ts`, `oanda.ts`) take an injected `fetch` and page until the range is covered; `store.ts` is the only Prisma access (owner-scoped). One migration adds `LabDataset`. No UI here (P11b-3).

**Spec:** `docs/superpowers/plans/2026-10-20-p11-honest-numbers-and-strategy-lab.md` § P11b.

## Global Constraints
- Never invent bars: a provider error or an empty page stops the fetch with a readable error; partial ranges are stored only with their real `from`/`to`.
- Times are epoch ms UTC. Bars are strictly increasing in time; duplicates from overlapping pages are dropped.
- OANDA is read with the user's own connection token, read-only endpoints only (`/v3/instruments/{i}/candles`).
- Caps: ≤ 10 datasets per user, ≤ 40 MB compressed per dataset, ≤ 2 years of 1-minute bars per fetch.
- `server-only` on every file that touches Prisma, secrets or the network.

## Files
| File | Responsibility |
|---|---|
| `lib/lab/data/encode.ts` | `encodeSeries(bars, spread?) → Buffer` (gzip of Float64 columns), `decodeSeries(buf)` |
| `lib/lab/data/mt5csv.ts` | `parseMt5Csv(text) → { symbol, bars, spread }` with readable errors |
| `lib/lab/data/binance.ts` | `fetchBinanceHistory({ symbol, interval, from, to }, deps)` — paged spot klines (1000 per call) |
| `lib/lab/data/oanda.ts` | `fetchOandaHistory({ conn, instrument, granularity, from, to }, deps)` — paged bid/ask candles (5000 per call), mid prices + spread |
| `lib/lab/data/store.ts` | `saveDataset`, `listDatasets`, `loadDataset`, `deleteDataset` — owner-scoped, caps |
| `prisma/schema.prisma` + migration | `LabDataset { id, userId, symbol, source, timeframe, fromAt, toAt, bars, hasSpread, blob Bytes, sizeBytes, createdAt }` |

## Tasks
1. **encode.ts** — round-trip test (with and without spread), gzip actually shrinks a flat series, a corrupt buffer throws `LabDataError`.
2. **mt5csv.ts** — parses the exact `ExportM1.mq5` header and rows; spread = `spread_points × point`; symbol from `symbol=` in the header; rejects a wrong header, non-numeric rows, and time going backwards (with the line number); drops duplicate times.
3. **binance.ts** — fake fetch serving pages of 1000; the fetcher advances `startTime` past the last open time, stops at `to`, dedups the overlap, errors on HTTP failure and on an empty first page.
4. **oanda.ts** — fake fetch serving `price=BA` candles with `Accept-Datetime-Format: UNIX`; mid = (bid + ask) / 2 for o/h/l/c, spread = ask.c − bid.c; only `complete` candles; pages by `from` with `includeFirst=false`; `Authorization: Bearer <decrypted token>`; host by `sandbox`.
5. **schema + store.ts** — DB tests: save/load round trip, another user cannot load or delete, the 11th dataset is refused, a blob over the cap is refused, list returns metadata without blobs.
6. Gates: `tsc`, ESLint, `npm run test:db`, build; commit; Notion card → Done.
